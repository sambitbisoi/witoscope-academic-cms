# Plan: Science review Q11, Q12, Q15, Q16, Q17, Q18 (16 Nov 2026)

> Approved by Sambit, 16 Nov 2026, with the decisions in §8. Built as PRs A–C.

## Context
There are 134 Science questions (SQ000135–268, Magnets C6 Ch 4, all at v1 **Needs review**) linked to 2,407 content rows. Today, three things are free text or implicit. (1) The misconception a question targets is plain text, and wrong options have no misconception tag. (2) All direct rows count the same. (3) The explanation has no rule. Sambit wants these tied to the content rows: misconception *items* on each row, one primary row per question, and Solution 1 written from the rows. The row's class should also be visible on screen (Q11, Q12), and a question should be addable straight from a row (Q15).

## 3. Importer and rationaliser

| Tool | Change |
|---|---|
| `import:science` | After the content-row upsert, **split each row's misconceptions into items** with the shared `splitMisconceptions` and the stored decisions. Same text at the same position is unchanged. Changed text: update in place, audited [inferred]. Extra item: next number. Item gone: retired, and any question that uses it is listed. Items with source `from question` are never touched. Questions: `Misconception targeted` is matched to an item of the linked rows (also accepts a direct "C6-04-014 #1"). **Only references are written**; the text goes to `_legacy`; unmatched ones go in the report. Ranks: one direct row → primary; several → proposed by the same rule as the rationaliser |
| **`scripts/science-rationalise.ts`** (`npm run science:rationalise -- [--dry-run] [--confirm-real]`) | One transaction; `--dry-run` rolls back. Steps: (1) split rows (rules below + my reviewed decisions file `scripts/lib/science-splits.json`, our own text only); (2) match each Science version's misconception: **exact** (normalised) → matched; **fuzzy** (token overlap ≥ 0.7 with exactly one item) → matched-fuzzy, listed; two or more candidates → **ambiguous**, best one proposed; none on linked rows → **unmatched**: if the same item exists on an unlinked row, say so; otherwise propose a new item on the primary row (`needs_review`, source `from question`) or propose clearing it; (3) copy to legacy, then clear; (4) tag wrong options whose text matches an item of a linked row, and list the untagged ones; (5) ranks and primary proposals; (6) Solution 1 drafts for the listed questions. Only open drafts are touched; an approved Science version is reported and left alone (none today) |
| Split rules | Split on ";" and on ". " + capital letter. **Not split:** abbreviations (J.C.); a clause that corrects ("in fact", "actually"); a second clause that only explains the first (my judgement, noted in `split_note`). "; or," → two items. Each decision is listed |
| Guards (stop conditions, checked inside the transaction) | md5 of every non-Science row in `cms_questions`, `cms_question_versions`, `cms_version_*` and `cms_question_content_rows`, taken before and after, must match. Every Science legacy value equals the old text. Unclear splits ≤ 10% and unmatched ≤ 25%, otherwise the script aborts with its report |
| Report | `.local-import/science-rationalise-{local,real}[-dry-run]-<ts>.json` + `.md`. **Counts table:** rows split / kept whole / unclear, items created, questions matched exact / fuzzy / ambiguous / unmatched / none, wrong options tagged / untagged, primary set / proposed, solutions drafted. **Lists:** unclear splits; ambiguous and unmatched with proposals; the 19 primary proposals (row IDs + reason); drafted solutions (old → new); untagged wrong options. IDs and our own text only |
| `db:verify` | New checks: every misconception ref is an item of a linked row · at most one primary per version and rank consistent with role · no Science `misconception_targeted` text left · legacy filled wherever the text was before · item numbers contiguous per row · no item text over 300 characters |

## 8. Decisions (Sambit, 16 Nov 2026) — approved; "go" given
1. Misconception targeted is **optional**; if set, it must be a row item. Wrong-option tags work the same way.
2. **Yes:** a question that uses a needs-review item stays blocked. The item is approved or retired in a status-only **"Misconception items"** tab in Proposed.
3. **Yes:** approval is blocked until the primary is confirmed.
4. **Yes:** when the targeted text is on an unlinked row, link that row as **supporting** (listed, audited) instead of making a duplicate item.
5. Under **60 characters** → a draft is written. Also **list (no drafts)** the questions whose Solution 1 never mentions a wrong option.
6. **Yes:** drafts replace Solution 1 in place, audited, and the question stays Needs review.
7. **Yes:** the tag reads "Class 5 row · lower class".
