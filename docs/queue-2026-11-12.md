# CMS work queue — agreed 12 Nov 2026

Agreed by Sambit in the architect/reviewer chat while reviewing Class 5–6 Math in the local CMS. **Track:** **App** = the CMS repo session (this repo: schema, importers, screens); **Data** = the Math data session in `~/WitoScope/ContentResearch/` (content files only — never this repo or the DB); **Later** = deferred, don't build. Data outputs land in `~/WitoScope/ContentResearch/CMS-updates/` in the formats under "File contracts"; the App track builds importers for them and merges everything into the **local** DB.

## File contracts (Data → App)

All UTF-8 CSV with a header row, in `~/WitoScope/ContentResearch/CMS-updates/`. `file_key` = the question key used in the pipeline chapter files and `cms_questions.file_key` (e.g. `MC04-0007`). Data writes a `README.md` there listing each file, row counts and anything unresolved.

| File | Columns | Notes |
|---|---|---|
| `question_levels.csv` | `file_key, level, source_file, source_field` | level = 1–6, the class the question is written for (from *Book class*) |
| `topic_classes.csv` | `topic_id, class, source, evidence` | one row per topic × class; source = NCERT / DAV / ISO / IXL / workbook-default |
| `settings_catalogue.csv` | `setting_id, name, description, theme, status` | setting_id = `SET001`…; status = `proposed`; includes `Bare` (no story) |
| `question_settings.csv` | `file_key, setting_id, confidence, note` | one setting per question; confidence high / medium / low |
| `near_copy_rewrites/<chapter file>.json` | same format as the pipeline `MC…-C….json` files | only the rewritten questions (C1), **same file_key**, so they import as a new version and replace the blocked draft |
| `key_fixes.csv` | `old_file_key, new_file_key, source_file, reason` | C3 (`MC19-0001`) and any other clashes |

## Design changes

| # | Item | Track | Notes |
|---|---|---|---|
| D1 | **Question Level** (1–6) | App + Data | Column on the question + display. Data: `question_levels.csv`. |
| D2 | **Topic ↔ many classes** | App + Data | Chapters are grade-agnostic, so this is topic ↔ classes. Mapping table in `cms` + importer for `topic_classes.csv`. After D5 edited in the CMS. |
| D3 | **Display rule** | App | A question shows in class N if its topic is mapped to class N **and** Level ≤ N. Lower-level = revision in higher classes; higher-level never in lower classes. |
| D4 | **Topic prerequisites — placeholder** | App | `cms_topic_prereqs` (topic → prerequisite topic); edited on the topic screen (D5); in the Excel export; header shows "Prerequisites: —" or **ID + name**, linked. No data yet. |
| D5 | **CMS owns the curriculum** (Sambit, option B) | App | **Replaces hard rule 6 — update CLAUDE.md and docs/phase1-design.md.** Add + edit chapters, topics, concepts, typical sets, patterns (forms, explicit Save). No delete — Retire (hidden; ID + history kept). IDs automatic, never changed. Every change audited (before → after). New concepts / question types start Proposed. Topic screen edits D2 + D4. **Export to Excel** regenerates `WitoScope_{Math,Science,English}_Topics_Class1-6.xlsx` (Class View format + new columns) — the workbooks become read-only exports for the content pipelines. One-time cut-over: final workbook import, then switch (Sambit confirms the workbooks are final first). Achievers rows (Math) same rules. `import:sources` must stop depending on the workbooks. |
| D6 | **Review workflow** (Sambit) | App | Question buttons: **Edit · Needs review · Approve · Reject**. Needs review (optional note) → Review queue. Reject requires a comment; question stays, can be re-versioned. Nothing deletes; Retire button removed from the question screen (status kept in the model). Review tab = flagged + rejected with notes. Shortcuts A / R / F / ↓↑. |
| D7 | **Sources kept up to date** | App | Every content import registers its books + citations; manual "Add a source" stays; sources retired, never deleted. Book rule unchanged. |
| D8 | **Setting + pattern rule + clone groups** | App + Data | (a) **Setting** = the story/context of a question (Lift, Thermometer, Bank balance, **Bare**…): one per question, from a small catalogue (ID, name, description, theme, status). Importers for `settings_catalogue.csv` + `question_settings.csv`; show + filter by setting. (b) **Pattern rule**: a pattern is the **pure maths skeleton plus every constraint that changes the skill** (signs, crossing zero, carries, like/unlike denominators…), **never the story** — add to this repo's `claude/question-bank/generation-prompt.md` (and the Generate prompt in `shared/`). (c) **Clone groups** (computed): same pattern + same signature + same concepts/involvement = interchangeable. Show "1 of 5 clones", group clones in lists, topic header "20 Qs · 5 groups", label near-identical clones (never remove). Hierarchy: Topic → Typical set → Pattern → Clone group → Question (+ setting). |
